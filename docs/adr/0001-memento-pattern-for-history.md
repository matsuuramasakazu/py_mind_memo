# 0001. 変更履歴の管理にスナップショット方式（Mementoパターン）を採用する

## Context
マインドマップの編集操作（トピックの追加・削除、階層・位置のドラッグ移動、トピック間参照線の追加・制御点変形、画像・アイコン設定など）に対して、上限10回のUndo/Redo機能を実装する必要がある。
操作ごとの逆変換ロジックを実装する「コマンドパターン」と、状態全体を辞書シリアライズして保持する「スナップショット（メメント）方式」の2つの選択肢があった。

## Decision
スナップショット方式（Mementoパターン）を採用する。
変更確定時に `MindMapModel.save()` で出力される辞書データと選択中IDをリングバッファに保存し、Undo/Redo時に `MindMapModel.load()` で復元する。

## Reasons & Trade-offs
- **状態復元の完全性と堅牢性**: トピックの削除に伴う参照線の連動削除や、ドラッグによる親子関係の組み換え、左右自動配置の方向更新など、複数のエンティティが連動して変化する。コマンドパターンでは逆操作の網羅やエッジケース（参照線の制御点復元など）でのバグが多発しやすいが、スナップショット方式であれば完全かつ確実に過去の状態を復元できる。
- **メモリ効率とのトレードオフ**: 通常のマインドマップデータは数百ノード程度でも数十KB程度であり、履歴上限を10件に固定するため、メモリフットプリントは最大でも数百KB〜数MBに収まり実用上の問題は皆無である。
